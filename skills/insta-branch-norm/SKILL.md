# insta-branch-norm

## Purpose

本技能旨在帮助用户规范git分支的使用，确保每次开发都在合适的分支上进行，开发过程可追溯且易于管理和维护。本技能**只提供流程原则指导和用户询问建议**，不直接执行具体git命令或硬编码任何步骤。所有git操作均需由模型根据项目实际情况灵活选择命令，并严格遵守安全原则和用户确认流程。

本技能**只做DML-like的git操作指导**，不做任何破坏性或权限相关的git命令。

## 核心原则

- **分支创建**：新分支必须从 `main` 分支创建，除非用户明确指定其他分支来源。禁止从feature分支、tag或其他分支创建。
- **分支命名规范**：新分支名称应使用 `feat/` 或 `fix/` 前缀，描述功能或问题（如 `feat/user-login`、`fix/api-rate-limit`），便于后续追溯和归档。
- **开发前确认流程**：在开始任何开发工作前，必须询问用户以下内容：
  1. 当前分支是否适合本次开发？（例如是否在 `main` 上还是已有feature分支）
  2. 是否需要创建新分支？（默认推荐创建新分支，以便功能隔离）
  3. 如果创建新分支，分支名称是多少？（默认从 `main` 创建）
- **提交推送规范**：功能完整开发完毕后，必须先提交代码并推送到远程仓库。具体流程：
  1. 询问用户提交信息（commit message，例如 "feat: add user authentication"）
  2. 执行提交操作
  3. 推送到远程
- **测试分支推送**：推送当前分支后，必须检查远程 `test` 分支是否存在：
  - 若存在，则将当前功能推送到 `test` 分支（推荐先 merge 当前分支到 test 分支，或 rebase 后再 push）。
  - 若不存在，则可询问用户是否创建 `test` 分支并推送。
- **子模块处理**（仅当项目存在 `insta-backendApi-docs` 时）：
  - 确认子模块指针是否指向最新状态。
  - 若开发涉及接口变动，必须在子模块目录 `insta-backendApi-docs` 中维护/更新文档内容。
  - 然后执行子模块的 git add、commit 和 push。
  - 最后更新项目根目录的子模块指针（使用 `git submodule absorbgitdirs` 或类似安全命令）到最新状态。
- **整体工作流程顺序**（必须严格遵守）：
  1. 分支确认与创建/切换（询问 + 执行）
  2. 功能开发
  3. 开发完毕 → 提交并推送到远程
  4. 检查 test 分支并推送
  5. 处理子模块（若适用）
- **安全与确认边界**：
  - 任何涉及 `git commit`、`git push`、`git add` 的操作前，必须向用户明确确认并获得授权。
  - 禁止直接操作远程仓库除非用户明确授权。
  - 优先使用只读命令（如 `git status`、`git branch -r`）检查状态，再决定下一步。
  - 如果不确定分支状态或子模块状态，必须先询问用户确认。

## 执行建议与灵活性

本技能鼓励模型使用项目中已存在的脚本或工具（如现有 Node.js 脚本、prisma migrate 等）来实现 git 操作，但必须保持与本技能描述的一致性。不要假设具体命令行工具或脚本，必须根据当前目录的实际情况灵活选择。

## 触发条件

本技能在用户提及以下任意关键词或情境时强烈推荐触发：
- 分支、git分支、new branch、test branch、main 分支、git workflow、submodule、insta-backendApi-docs、开发流程、git pull、git push、git commit

## 输出格式

每次使用本技能时，应清晰输出以下结构：
- 当前分支状态
- 用户确认的下一步行动
- 执行计划（步骤列表）
- 最终输出结果
